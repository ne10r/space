# Учебный конфигурационный язык — вариант 21

Перевод конфигурационного языка из `бебра.pdf`, страницы 47–48, в XML.
Полное решение находится в ветке `main` репозитория `ne10r/space`.
Локальная папка называется `bebra`. Исходные PDF в Git не добавляются.
Используется специализированный Lark LALR parser и отдельная грамматика
`src/grammar.lark`. Регулярные выражения описывают только терминалы;
вложенные конструкции разбирает Lark, не самописный разбор строк.

## Установка и запуск

Нужен Python 3.9 или новее. Команды выполняются из корня проекта:

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements-dev.txt
.venv/bin/python -m src.main < examples/basic.conf
make run PYTHON=.venv/bin/python
make demo PYTHON=.venv/bin/python
make test PYTHON=.venv/bin/python
make style PYTHON=.venv/bin/python
```

Вход только из stdin, XML только в stdout. Для записи используйте
перенаправление `> build/result.xml` после создания каталога `build`.
Диагностика идёт в stderr; при ошибке stdout пуст. Коды завершения:
0 — успех, 1 — ошибка входа/перевода, 2 — неизвестный аргумент CLI.
Дополнительных параметров, кроме `--help`, нет. `PYTHON` и `SOURCE`
настраивают Makefile; по умолчанию SOURCE=examples/web.conf.

## Язык

Числа строго соответствуют `[+-]?\d+\.\d+`: целые числа, exponent,
`.5`, `1.` не допускаются. Decimal сохраняет точность и конечные нули.
Имена соответствуют `[A-Z]+` и чувствительны к регистру.
Строки заключаются в одинарные кавычки, могут содержать переводы строк.
Backslash — обычный символ, escape-последовательности не добавлялись.
Апостроф внутри строки не поддерживается, поскольку PDF не задаёт
его экранирование. Комментарии `{- ... -}` многострочные, невложенные.

Словарь: `$[NAME: value, OTHER: value]`. Допускаются пустой словарь,
вложенные словари и одна завершающая запятая. Дубли ключей запрещены.
Документ содержит одно корневое значение; оно может быть любого типа.
Начальный UTF-8 BOM допускается. Расширения языка и ограничения явно
документируются ниже.

## Константы

`значение -> ИМЯ` объявляет константу, `@(ИМЯ)` подставляет её значение.
Перед корневым значением можно указать любое число объявлений, разделённых
пробелами или переводами строк. Внутри словаря объявление является
отдельным элементом списка и отделяется запятой, как обычное поле:

```text
12.50 -> RATE
$[DEFAULT: @(RATE), LOCAL: $[2.0 -> RATE, VALUE: @(RATE)]]
```

Константой может быть число, строка, словарь и ссылка на ранее объявленную
константу. Объявления не выводятся в XML. Вычисление идёт слева направо;
forward/self references запрещены. Переобъявление в одной области — ошибка.
Каждый словарь создаёт локальную область: видны внешние имена, допускается
их затенение, но локальные объявления не выходят за пределы словаря.
Ключи словаря и константы имеют разные пространства имён. Эти правила
уточняют не заданную в PDF область видимости; сами символы синтаксиса
сохраняются. Смотрите `examples/constants.conf`.

## Формат XML

Корневой элемент `config`. Имя словарного поля становится XML-тегом.
Атрибут `type` принимает `dictionary`, `number` или `string`: это отличает
строку `'1.0'` от числа и пустую строку от пустого словаря. Сохраняется
порядок полей. XML-символы экранирует ElementTree; DTD не создаётся.
Недопустимые для XML 1.0 управляющие символы и surrogate code points
отклоняются с позицией строки. CR внутри строки выводится как `&#13;`,
чтобы XML-reader не заменил его переводом строки. Пустые/пробельные строки
сохраняются. При превышении глубины рекурсии Python выводится понятная
ошибка; пользовательская квота вложенности не вводилась.

## Функции

| Модуль | Назначение функций |
| --- | --- |
| parser | parse_source: Lark AST или ошибка с позицией |
| evaluator | evaluate_document: корень; evaluate_value: тип значения |
| evaluator | evaluate_dictionary: ключи и значения; source_error: позиция |
| evaluator | define_constant: объявление; resolve_constant: поиск по областям |
| evaluator | evaluate_string: содержимое и проверка XML-символов |
| xml_writer | make_element: XML-узел; to_xml: документ UTF-8 |
| xml_writer | is_xml_character: допустимый символ XML 1.0 |
| main | convert: полный перевод; main: CLI stdin/stdout |
| scripts/demo | run_example: настоящий CLI; main: три примера и отчёт |

Тесты проверяют типы значений, вложенность, комментарии, XML escaping,
синтаксические ошибки и повторные ключи. `scripts/check_style.py`
проверяет размеры функций/строк, docstring, snake_case функций и
именованные числа в сравнениях. Бинарники, окружение и сборка игнорируются.

CLI дополнительно проверяется отдельными процессами: stdin/stdout/stderr,
UTF-8, пустой stdout при ошибке, `--help`, неверные опции и номер строки.
Проверки вложенности включают составные константы, локальное затенение,
40 уровней словаря и обработку превышения рекурсии Python.

## Три предметные области

```bash
.venv/bin/python -m src.main < examples/web.conf
.venv/bin/python -m src.main < examples/laboratory.conf
.venv/bin/python -m src.main < examples/game.conf
.venv/bin/python -m scripts.demo
```

| Файл | Предметная область | Что демонстрирует |
| --- | --- | --- |
| web.conf | Веб-сервис | HTTP, БД, вложенный пул, константы host/port |
| laboratory.conf | Лаборатория | Калибровка, отрицательное число, XML escaping |
| game.conf | Игра | Константа-словарь, локальная скорость, вложенные настройки |

Порты и размеры записаны с дробной частью, поскольку именно такой формат
чисел задан вариантом. Названия полей не содержат цифр или подчёркиваний.
Все примеры включают комментарии, строки, числа, словари и ссылки.

Например, `1.25 -> RATE $[VALUE: @(RATE), NOTE: 'A & B']` даёт:

```xml
<?xml version='1.0' encoding='utf-8'?>
<config type="dictionary">
  <VALUE type="number">1.25</VALUE>
  <NOTE type="string">A &amp; B</NOTE>
</config>
```

Демонстрация передаёт каждый файл в stdin отдельного процесса переводчика,
проверяет полученный XML, сохраняет результаты в `build/examples/*.xml`
и фактические контрольные значения в `reports/examples.json`. Сборка XML
не зависит от этих эталонных значений: ими пользуется только демонстрация.
Библиотека переводчика не вызывает shell, eval или exec.
